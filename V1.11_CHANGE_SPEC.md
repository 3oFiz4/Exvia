# Exvia v1.11 change specification

## 1. Developer Options

- Triple-tap the **Exvia** title within approximately 1.1 seconds between taps.
- Developer Options are enabled by default on a fresh installation.
- Toggling is persisted locally and recreates the activity immediately.
- When Developer Options are hidden, Settings omits:
  - GitHub
  - Schema & Display
  - Custom metric
  - Custom plot
- Color, Interface, Report, Save, and Close remain available.

## 2. Regular-mode filtering

When Developer Options are hidden:

- The SQL-like filter input is not displayed.
- It is replaced by **Filtering method**.
- The method selector displays snippet names only.
- The underlying SQLite-style syntax remains hidden.
- Built-in and saved methods are separate collapsed accordions.
- The selected method still replaces the effective Table dataset and therefore also recalculates Stat, finance metrics, plots, and custom metrics.

When Developer Options are enabled:

- The query input is visible.
- Holding it for one second opens the full Filtering Snippet manager.
- Full query syntax and snippet CRUD remain available.

## 3. Interface scaling

Settings includes an **Interface** accordion:

- `display.ui_scale`: scales density-based margins, padding, dimensions, and control heights. Range: 0.70–1.60.
- `display.text_scale`: scales application text independently. Range: 0.70–1.80.

Changes apply after **Save settings and reload**.

## 4. Synchronized configuration

Every successful **Save settings and reload** attempts to create or update:

```text
Financial/.exvia-config.json
```

The file is hidden from the Files section. Dot-prefixed JSON filenames are also reserved and hidden.

The synchronized file contains:

- repository metadata;
- schema overrides;
- display and plotting columns;
- finance columns;
- ticker colors;
- UI and text scales;
- theme palette;
- custom metrics;
- custom plots;
- filtering snippets;
- Developer Options state;
- report repository.

The GitHub PAT is deliberately excluded. It remains encrypted locally with Android Keystore.

If no PAT or configured repository exists, settings are saved locally and Exvia reports that remote synchronization could not be performed. If the GitHub write fails, the app keeps the local settings and displays a retry message.

## 5. Collapsed built-in examples

- Built-in filtering examples are under a collapsed **Built-in examples/methods** accordion.
- Built-in custom JavaScript metric templates are under a collapsed **Built-in metric examples** accordion.
- User-created snippets and metrics remain separate from built-ins.

## 6. GitHub Issue reporting

Settings includes a **Report** button.

The report dialog contains:

- classification dropdown: Bug, Enhancement, Feature;
- multiline description input.

Issues are created in:

```text
<github.owner>/<github.report_repo>
```

The default report repository is `finance_app`.

Issue title prefixes are:

```text
bug:
ench:
feat:
```

The PAT must have Issues write permission for the target repository. The submitted issue body includes the report text and minimal Exvia context. No expense JSON content or PAT is attached.
