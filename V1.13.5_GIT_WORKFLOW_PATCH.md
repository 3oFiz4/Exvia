# Exvia v1.13.5 — Git workflow / manual amend patch

This patch intentionally keeps `versionCode = 22` and `versionName = "1.13.5"`.

## Git panel

A **Git** button is displayed immediately beside **Re-sync** in the top bar.

The panel provides:

1. paginated commit history (`15` commits/page);
2. Previous / Next commit-page navigation;
3. a history-preserving repository revert action for any non-HEAD commit;
4. **Re-sync · Pull** for the configured branch;
5. **Amend · Stage → Commit → Push** for the selected Table stage.

The revert operation does not force-reset the branch to an old SHA. Exvia reads the selected commit's tree, creates a new commit using that tree with the current HEAD as parent, and advances the configured branch to the new commit. This restores the old repository contents while retaining the intervening history.

## Persistent local Table stage

New data-layer component:

```text
data/local/LocalStagingStore.kt
```

When `automaticAmend = false`, Table CRUD does not call the Contents write endpoint. Exvia instead saves the effective JSON rows under app-private storage in a repository/branch-scoped stage.

Each stage stores:

- selected repository path;
- remote file SHA at the start of the stage;
- complete current staged rows;
- compact list of pending commit messages;
- update timestamp.

The remote response cache and the stage are deliberately separate. A restart can therefore reopen the stage without pretending it is the last fetched GitHub state.

## Git amend mode

New `RepoSettings` field:

```kotlin
val automaticAmend: Boolean
```

Default: `true`.

Settings UI choices:

```text
Automatic · Commit immediately
Manual · Stage locally
```

The setting is saved in SharedPreferences and synchronized in `.exvia/.exvia-settings.json`.

## Manual Amend

With manual mode enabled:

- Amend appends to local staged rows;
- Edit Row updates local staged rows;
- Delete Row removes from local staged rows;
- Undo/Redo replaces the staged row array rather than making an intermediate remote commit;
- switching between previously staged files reloads each file's stage;
- app restart reloads the selected stage.

Pressing **Git → Amend**:

1. loads the selected local stage;
2. fetches the current remote file SHA;
3. aborts if the remote SHA no longer matches the stage base SHA;
4. writes the staged rows with one commit;
5. refreshes the GitHub cache/index;
6. removes the completed stage.

## Pull / Re-sync

The top Re-sync and the Git-panel Pull use the same explicit pull flow.

- With no local stage, the configured branch is refreshed immediately.
- With one or more stages, Exvia asks before discarding **all** local stages.
- After confirmation, the stage store is cleared and the repository list/current file are fetched again.

## Undo / Redo correction

Undo/Redo remains a compact row-delta history (maximum `1–50`, default `50`) rather than storing 50 entire tables.

The correction ensures:

- `canUndo` / `canRedo` are synchronized with the actual stacks after successful mutations;
- history stack movement occurs only after `replaceRows` succeeds;
- Automatic mode restores the remote JSON as a commit;
- Manual mode restores the local staged rows only;
- the staged-state flags published to the Activity distinguish the selected-file stage from stages elsewhere in the repository.

Smoke tests cover Amend → Undo → Redo, Edit → Undo, and Delete → Undo under both Automatic and Manual stage modes.

## Commit history API

`GitHubApi` now provides branch commit pagination and Git-database helpers for tree-based revert commits. The existing Contents API continues to handle ordinary Table commits.

## Scope

The manual stage applies to **Table row CRUD and Undo/Redo**. File create/delete, `.exvia/` resources, report Issues, and Files SQLite-script output remain immediate GitHub operations.
