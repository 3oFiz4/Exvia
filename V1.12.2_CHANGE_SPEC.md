# Exvia v1.12.2 change specification

## 1. Complete-SVG zoom

### Previous behavior

The history graph transformed an internal marks group while separately recalculating axes. Observable plots used a CSS transform on the chart node. On some Android WebView/device combinations this made pinch gestures register without making the complete SVG appear to resize.

### New behavior

`helpers.attachZoom` resolves the actual SVG and controls its `viewBox`.

For a D3 zoom transform `(x, y, k)`, the visible viewport becomes:

```text
viewBox.x      = baseX - x / k
viewBox.y      = baseY - y / k
viewBox.width  = baseWidth / k
viewBox.height = baseHeight / k
```

The implementation also converts between host CSS pixels and SVG user units where the host dimensions differ from the SVG dimensions.

This applies uniformly to:

- D3 history plot;
- Observable accumulation plot;
- Observable normal-distribution plot;
- custom SVG/Observable plots using `helpers.attachZoom`.

### Interaction correctness

Observable plot inspection now maps client coordinates into SVG coordinates through:

```javascript
svg.createSVGPoint()
svg.getScreenCTM().inverse()
```

This keeps nearest-point selection correct after zoom and pan.

## 2. GitHub report form

The dialog requires:

- classification;
- title;
- description.

The issue title is no longer synthesized from the first description line. It uses the explicit Title input.

Classification mapping:

```text
Bug         -> #bug
Enhancement -> #ench
Feature     -> #feat
```

`GitHubApi.createIssue` now accepts a label list. Before posting the issue, Exvia ensures each selected label exists using the repository labels endpoint. The issue request includes the labels array.
