# Exvia v1.13.7 change specification

v1.13.7 introduces native Android App Widgets for Exvia, allowing users to view target expense files and perform quick amends directly from their Android Home Screen, adhering strictly to Exvia's MVVM architecture.

## 1. Native Android App Widget (`ExpenseAppWidgetProvider`)

An Android Home Screen widget implemented via `ExpenseAppWidgetProvider` and `RemoteViews`, styled after `prototype/widget_idea.html`:

- **Target File Header**: Displays the configured target JSON file (`--> <filename>`, e.g., `--> september_expenses.json`) in `#CBD5E1` (slate-300) with monospace formatting.
- **Listing All Possible Fields**: The widget checks the default file configuration and repository cache/staging to dynamically list every field that exists in the targeted file (and schema rules), including date, price, description, category, tags, and any custom columns.
- **Scrollable Field Container (`ListView`)**: When the number of fields exceeds the available container height of the widget, an integrated `ListView` (backed by `ExpenseWidgetRemoteViewsService` and `ExpenseWidgetViewsFactory`) provides smooth vertical scrolling.
- **Non-radial Outer Border**: In accordance with design requirements, the outer border of the widget container is non-radial (`0dp` corner radius / rectangular border) with a `1dp` red `#F72323` stroke and solid black `#000000` background.
- **Input Styling**: Each field row is rendered with a bottom-line red border (`1dp` `#F72323`), white text `#EDEDED`, and muted placeholder text `#7D7D7D`. The Date field displays the auto-added date formatted as `d/M/yy @ HH:mm` (e.g. `10/09/26 @ 03:39`). Price displays a `0.00` placeholder.
- **Amend Button**: Rendered with black background, `1dp` red border `#F72323`, and `8dp` rounded corners (`rounded-lg`).
- **Status Log Line**: Displays `log: Ready` or `log: Data amended` in green `#86EFAC` (`text-green-300`), matching Exvia's status log.

## 2. Interactive Quick Amend Dialog (`WidgetEntryActivity`)

Because Android Home Screen `RemoteViews` operates across process boundaries and explicitly does not support soft-keyboard input or `EditText` directly on the launcher, tapping on any field row or tapping the Amend button launches `WidgetEntryActivity`:

- Styled as a sleek, translucent floating native Android dialog over the Home Screen.
- Card dimensions match `prototype/widget_idea.html` (500dp max width, black background `#000000`, non-radial red border).
- Applied with JetBrains Mono typeface (`AppFonts.jetBrains`).
- **Dynamic Form Generation & Scrolling**:
  - Automatically loads and lists all possible fields from the target file, filtering out imaginary fields and hidden schema fields.
  - Form is housed in a `ScrollView` ensuring scrollability when fields exceed the dialog height.
  - Automatically pre-fills current date/time (`d/M/yy @ HH:mm`) on the date field.
  - Fields use standard text input (`InputType.TYPE_CLASS_TEXT`) allowing full alphanumeric input, formulas, and currency without a forced numeric keypad.
  - Soft keyboard remains hidden until a specific field is explicitly tapped by the user.
- **Working Auto-completer**:
  - Uses native `AutoCompleteTextView` (and `MultiAutoCompleteTextView` with comma tokenizing for tags).
  - Suggestions are computed by frequency analysis over existing table rows in the repository cache (`suggestionsForKey`).
  - Dropdown uses JetBrains Mono font with dark surface background (`#1F1F1F`) and white text.
- **Amend Action**:
  - Validates and transforms inputs (including schema rules such as `0/1` boolean conversions).
  - Persists the new row through `ExpenseRepository.appendRow()`.
  - Dispatches automation notification events (`event.amend`) via `NotificationDispatcher`.
  - Updates the status log to `log: Data amended` in `#86EFAC`.
  - Broadcasts immediate update to all Home Screen widget instances so the Home Screen widget reflects `log: Data amended` and refreshes its fields.

## 3. RemoteViews Service (`ExpenseWidgetRemoteViewsService`)

- Implements `RemoteViewsService` and `RemoteViewsFactory` to manage the collection of fields in the Home Screen widget.
- Binds `setPendingIntentTemplate` and `setOnClickFillInIntent` to allow clicking any specific field row to open the quick-amend dialog pre-focused on that field.
- Registered in `AndroidManifest.xml` with `android.permission.BIND_REMOTEVIEWS`.

## 4. MVVM Architecture

The widget feature is built in conformance with Exvia's MVVM architecture:

- **Presentation Layer**:
  - `presentation/widget/ExpenseAppWidgetProvider.kt`: AppWidgetProvider managing RemoteViews and click PendingIntents.
  - `presentation/widget/ExpenseWidgetRemoteViewsService.kt`: Service providing dynamic scrollable collection items.
  - `presentation/widget/WidgetEntryActivity.kt`: View component rendering the interactive dialog.
  - `presentation/widget/WidgetViewModel.kt`: ViewModel coordinating UI state, suggestions calculation, and amend operations.
  - `presentation/widget/WidgetUiState.kt`: Immutable state data model.
- **Domain Layer**:
  - `domain/repository/ExpenseRepository.kt`: Used directly for `appendRow` and workspace mutations.
  - `domain/model/settings/RepoSettings.kt`: Resolves `defaultJson`, date/money/tags key detection, schema rules, and imaginary fields.
- **Data Layer**:
  - `data/local/SettingsStore.kt`, `data/local/ExviaFileCache.kt`, `data/local/LocalStagingStore.kt`, `data/local/TokenStore.kt`.
