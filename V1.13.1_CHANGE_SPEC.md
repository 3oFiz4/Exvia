# Exvia v1.13.1 change specification

## 1. Paginated Table dataset

The Table stores the currently effective `TableData` as its pagination source. The effective dataset is the full selected JSON file when filtering is disabled and the filtered subset when filtering is enabled.

Page calculations use:

```text
pageCount = max(1, ceil(rowCount / rowsPerPage))
start = pageIndex * rowsPerPage
end = min(start + rowsPerPage, rowCount)
```

Only `rows[start until end]` is rendered. The original `DynamicRow.originalIndex` is retained, so row edit/delete behavior remains correct after filtering and pagination.

## 2. Navigation controls

A compact row appears below the Table with:

- **Previous** button;
- `Page n / total` indicator;
- **Next** button;
- **Rows** numeric input.

Previous is disabled on page 1. Next is disabled on the final page. Both controls follow the existing borderless-at-rest button styling.

## 3. Page-change overlay

A `TextView` overlay is hosted above the table scroll area in a `FrameLayout`.

- Text: `Page n`.
- Fill: current Tertiary UI color.
- Border: current Primary UI color.
- Text: current Senary UI color.
- Position: centered within the visible table area.
- Visibility: shown after successful Previous/Next navigation and faded after approximately 850 ms.

Repeated navigation cancels the earlier hide callback and updates the existing overlay instead of creating additional views.

## 4. Rows-per-page configuration

`RepoSettings` adds:

```kotlin
val rowsPerPage: Int
```

The accepted range is 1–500 and the default is 25.

The value is editable from:

- the compact Table pagination input; and
- Settings → Interface → `display.rows_per_page`.

Inline changes are saved immediately to SharedPreferences. Full settings saves include the value in the synchronized configuration under:

```json
{
  "display": {
    "rowsPerPage": 25
  }
}
```

## 5. Reset and clamping behavior

- A new file, changed filter, enabled/disabled filter, or refreshed dataset resets the page index to 0.
- Changing rows per page resets to page 1.
- If the dataset becomes smaller, the page index is clamped to the new final page.
- Empty datasets display `Page 1 / 1` with both navigation buttons disabled.

## 6. Compatibility

- Statistics still receive the complete effective filtered dataset, not only the visible page.
- GitHub writes still operate on the full JSON file.
- Existing cache, CRUD, themes, filtering snippets, custom metrics, custom plots, and semantic zoom remain unchanged.
- Logo files remain intentionally omitted.
