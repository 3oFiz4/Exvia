# Exvia v1.13.2 change specification

## Scope

This release changes architecture and package identity without intentionally changing the application's visible features or business rules.

## Package

```text
namespace     = xyz.x3ofiz4.exvia
applicationId = xyz.x3ofiz4.exvia
versionName   = 1.13.2
versionCode   = 19
```

`xyz.3ofiz4.exvia` could not be used because `3ofiz4` is not a valid Java identifier.

## Architectural changes

### Presentation

- `MainActivity` is a View only: widget construction, dialogs, transient overlays, navigation, and rendering.
- `MainViewModel` owns workspace and table state plus repository mutations.
- `SettingsViewModel` owns settings, token metadata, configuration synchronization, repository bootstrap, and reports.
- `StatisticsViewModel` provides calculation-facing APIs.
- `MainUiState` and `SettingsUiState` are immutable state models.
- Errors and transient actions are one-shot effects rather than mutable Activity flags.

### Domain

- Split former monolithic models into `custom`, `repository`, `settings`, `table`, and `theme` packages.
- Added `ExpenseRepository` and `ConfigurationRepository` contracts.
- Kept filtering, statistics, built-in examples, and settings-text parsing as deterministic domain services.
- Removed Android color parsing and JSON serialization from domain theme models.

### Data

- `GitHubExpenseRepository` centralizes loading, sync, cache selection, CRUD, and file operations.
- `ConfigurationRepositoryImpl` centralizes local settings, encrypted token access, config upload, repository creation, and issue reports.
- `SelectedFileStore` owns selected-file persistence.
- `GitHubApi` remains the remote data source.
- `ExviaFileCache`, `SettingsStore`, and `TokenStore` remain local data sources.

### Application/core

- `ExviaApplication` is the process-level composition root.
- `ExviaContainer` assembles repositories and data sources.
- `ObservableState` and `EventStream` provide lifecycle-neutral state/effect delivery.
- `PlotThemeJson` serializes domain plot themes at the boundary.

## Preserved behavior

- Dynamic forms and JSON schemas.
- Table CRUD, filtering, pagination, and direct page jump.
- GitHub file selection, creation, removal, commits, cache, and Re-sync.
- Statistics, finance groups, custom metrics, custom plots, and plot engines.
- UI/plot themes and custom named themes.
- Developer Options, snippets, config synchronization, and reporting.
- Existing date, tags, autocomplete, ticker color, and commit-message rules.

## Compatibility

The new application ID creates a fresh Android sandbox. The old app can remain installed, but local state and its encrypted PAT are not migrated automatically.
