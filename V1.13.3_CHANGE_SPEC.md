# Exvia v1.13.3 change specification

## 1. Query modes

`TableQueryMode` contains:

```kotlin
FILTERING
FLAGGING
```

The Table uses one compact query input and one mode-aware toggle.

### Gesture behavior

- Hold Filter/Flag toggle for `1,000 ms`: switch mode.
- Hold the query input for `2,000 ms`: open the current mode's manager.
- Cancel on early release, movement past touch slop, `ACTION_CANCEL`, or a second pointer.

### Filtering

Filtering applies `SqlLikeFilter` to the source table. The matching subset becomes the effective Table and Statistics dataset.

### Flagging

Flagging applies the same matcher but does not alter the effective row set. It produces presentation rules for matching rows/cells.

## 2. Table-style rule model

```kotlin
data class TableStyleRule(
    val id: String,
    val name: String,
    val query: String,
    val foregroundScript: String,
    val backgroundScript: String,
    val contentScript: String,
    val enabled: Boolean,
)
```

Accepted assignment targets:

```javascript
table['MATCHING_ROW'].fore
table['MATCHING_ROW'].back
table['MATCHING_ROW'].content

table['MATCHING_ROW']['COLUMN'].fore
table['MATCHING_ROW']['COLUMN'].back
table['MATCHING_ROW']['COLUMN'].content
```

The script parser is constrained and does not evaluate arbitrary JavaScript. It recognizes assignment-shaped text and only permits the three presentation properties above.

Content interpolation supports:

```text
$value
${COLUMN_NAME}
```

## 3. Style precedence

Rules are resolved in order:

1. enabled automatic Color Mapping rules;
2. active Flagging rule, when Flagging is enabled.

Later assignments override earlier assignments for the same row/cell property. Cell styling overrides inherited row styling.

## 4. Color Mapping

The legacy ticker-specific text mapping is migrated into generic `TableStyleRule` records. Color Mapping is automatic and independent from query mode.

Built-in defaults cover:

- positive `PRICE`;
- expense `PRICE`;
- example `CATEGORY` values `FD` and `BVG`.

The manager supports create, edit, enable/disable, remove, and restore defaults.

## 5. Persistence and GitHub files

Repository-root paths:

```text
.exvia/config.json
.exvia/table-rules.json
```

`config.json` contains ordinary settings, snippets, themes, custom metrics, custom plots, and rule definitions. `table-rules.json` is a focused automatically updated copy of Flagging and Color Mapping definitions.

The PAT remains encrypted locally and is excluded from synchronized JSON.

## 6. MVVM responsibilities

- `MainViewModel` owns Filtering/Flagging mode, automatic mappings, effective data, and resolved styles.
- `SettingsViewModel` owns local and remote rule persistence.
- `TableStyleEngine` performs Android-independent matching and assignment resolution.
- `MainActivity` owns gesture wiring, managers/editors, and rendering only.

## 7. Additional changes

- GitHub PAT copy/paste is enabled.
- Report target is fixed to `Exvia` under the configured GitHub owner.
- Save settings writes `.exvia/config.json`.
- Custom plots receive the shared plot zoom helper if not explicitly bound by their own script.
- Version bumped to `1.13.3` / code `20`.
