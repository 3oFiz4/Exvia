# Exvia v1.13.8 change specification

v1.13.8 introduces the **Receipt OCR Automaton** system in Exvia. This feature enables users to configure receipt scanning templates with interactive bounding boxes, connect them to target image folders, run customizable JavaScript and RegExp transformation pipelines on extracted values, and automatically extract expense entries using Google ML Kit Text Recognition directly into Exvia's financial ledger.

To keep initial download sizes small, the ML model is delivered as an **on-demand Add-on / Plug-in** via Google Play Services, saving ~15–20 MB from the base APK.

## 1. Settings Section: Receipt OCR Automaton

A dedicated section within the Settings drawer titled **Receipt OCR Automaton**:

- **OCR Add-on / Plug-in Management Banner**:
  - Displays dynamic module status: `● Installed (Ready)`, `○ Not Installed (~15 MB)`, or `⚠️ GMS Unavailable`.
  - Informs the user that the OCR model is optional to keep base app size minimal.
  - **📥 Install OCR Plug-in**: Action triggering background on-demand download via Google Play Services `ModuleInstallClient` with live percentage and MB progress indicators.
- **Active Template Cards**:
  - Displays each saved OCR template with real-time status (`● Enabled` in green or `○ Disabled` in muted gray).
  - Quick toggle button to switch templates between `Enabled` and `Disabled`.
  - Details overview showing target folder location, file name regex pattern, number of defined bounding boxes, and count of scanned receipts.
  - **Scan Now**: Trigger an on-demand scan of the target folder directly from Settings (prompts to install plug-in if uninstalled).
  - **Edit**: Launches the interactive OCR template editor for the selected template.
  - **Delete**: Prompts confirmation dialog and removes the template.
- **+ Add OCR Template**: Button to design and configure a new receipt scanning template.

## 2. Variables & Data Models

OCR templates and bounding boxes are modeled in `xyz.x3ofiz4.exvia.domain.model.custom`:

- **`OcrBoundingBox`**:
  - `name: String` (e.g. "Total Amount", "Date", "Store Name")
  - `posX: Float` (normalized horizontal start: `0.0f` to `1.0f`)
  - `posY: Float` (normalized vertical start: `0.0f` to `1.0f`)
  - `width: Float` (normalized width: `0.0f` to `1.0f`)
  - `height: Float` (normalized height: `0.0f` to `1.0f`)
  - `mapTo: String` (target JSON field from Exvia table, e.g. `price`, `date`, `description`, `category`)
  - `script: String` (custom JavaScript transformation script)
  - `regex: String` (optional post-script regular expression extraction or substitution)
  - *Normalized Coordinates*: Stored as relative floats rather than absolute pixels, ensuring that receipt templates work across camera resolutions, preview sizes, and aspect ratios.
- **`OcrTemplateDefinition`**:
  - `id: String` (UUID)
  - `name: String` (Template identifier)
  - `folderUri: String` (SAF persistable tree URI)
  - `folderDisplayName: String`
  - `fileNamePattern: String` (Regex pattern, e.g. `.*receipt.*\\.(jpg|png)`)
  - `boundingBoxes: List<OcrBoundingBox>`
  - `enabled: Boolean` (default `true`)
  - `lastScannedTimestamp: Long`
  - `processedFiles: List<String>` (tracks processed receipt files to prevent duplicate scans)

Persisted through `SettingsStore` in JSON format under key `ocr_templates` and exportable to `.exvia/receipt-ocr-templates.json` during workspace synchronization.

## 3. JavaScript & RegExp Transformation Pipeline (`ReceiptScriptEngine`)

For each bounding box, users can define a simple JavaScript script executed prior to mapping values into `mapTo`, followed by an optional regular expression filter/substitution.

### 4-Stage Default Script
Every bounding box includes or can be reset to the structured 4-stage pipeline template:
```javascript
/**
 * Receipt Value Processor
 * Pipeline: FILTERING -> PASS/NOT PASS -> MODIFY/SUBSTITUTE -> FINISH
 * @param {string} value - Raw OCR extracted text
 * @returns {string} - Modified value to map into Exvia (or null/empty to reject)
 */
function process(value) {
    // 1. FILTERING: Initial cleanup & trimming
    var text = (value || "").trim();

    // 2. PASS/NOT PASS: Validation criteria
    if (text.length === 0) {
        return ""; // Not pass: reject empty or invalid text
    }

    // 3. MODIFY/SUBSTITUTE: Clean, replace, or format
    // Example: strip non-numeric/currency characters and normalize decimal comma
    var modified = text.replace(/[^0-9.,]/g, "")
                       .replace(/,/g, ".");

    // 4. FINISH: Return target value
    return modified;
}
```

### Execution Pipeline
1. **Raw OCR Extraction**: Google ML Kit extracts raw text from the bounding box sub-bitmap.
2. **JavaScript Execution**: Evaluated via embedded Mozilla Rhino (`org.mozilla:rhino:1.7.15`) in interpreted mode (`optimizationLevel = -1`), compatible with both Android ART/Dalvik runtimes and JVM unit tests.
3. **RegExp Processing**: Evaluated on the intermediate JavaScript output. Supports:
   - Extraction: `\d+(\.\d{2})?`
   - Capture groups: `(?:Total:\s*)(\d+\.\d{2})`
   - Substitution syntax: `s/pattern/replacement/flags` (e.g. `s/,/./g`)
   - Filtering: non-matching inputs yield empty strings, rejecting noise.
4. **Final Value Mapping**: Cleaned value is assigned to the target row column specified in `mapTo`.

## 4. Visual Styling & Interactive Editor (`ReceiptOcrEditorActivity` & `ReceiptBoundingBoxOverlayView`)

- **Ultra-Thin Crisp Borders**:
  - Selected box border stroke is reduced to ultra-thin `0.85dp`, eliminating visual clutter over receipt text.
  - Selected corner resize handles are compact (`4.5dp` radius).
- **Unselected Transparency (Zero Borders)**:
  - Unselected bounding boxes have **no border stroke** (`borderWidth = 0`), displaying only an unobtrusive transparent background tint (`11%` opacity).
  - Unselected label badges are compact (`8.5sp` font) with no border.
  - Receipt text underneath remains completely visible and unblocked.
- **Unselect All / Deselect Action**:
  - Tapping empty receipt area or clicking `"Deselect"` unselects all bounding boxes, rendering the entire receipt with zero borders for full readability.
- **Theme Palette Integration**:
  - All UI elements, dialogs, badges, buttons, highlights, and borders dynamically match Exvia's active `ThemePalette` (`$primary`, `$tertiary`, `$quaternary`, `$senary`).
- **Interactive Script & RegExp Modal**:
  - Code editor using syntax-highlighted `JavaScriptCodeEditor`.
  - `"Insert Default"` button for instant template restoration.
  - Post-script RegExp pattern input.
  - **Live Test Sandbox**: Users can type custom test values (or auto-populate with the current box's raw OCR text) and click `"▶ Test Pipeline"` to view step-by-step transformations in real time (`Raw -> After JS -> Final`).

## 5. On-Demand Add-on / Plug-in Architecture (`OcrPluginManager`)

- Uses unbundled `com.google.android.gms:play-services-mlkit-text-recognition:19.0.1` and `com.google.android.gms:play-services-base:18.5.0`.
- Heavy ML weights and native binaries (`libmlkit_google_ocr_pipeline.so`) are completely excluded from the base APK, saving ~15–20 MB from the download size.
- `OcrPluginManager`:
  - Validates Google Play Services availability (`GoogleApiAvailability`).
  - Queries Google Play services `ModuleInstallClient.areModulesAvailable()` to verify if the model is present.
  - Dispatches on-demand model download via `ModuleInstallRequest` with progress callbacks.
  - Intercepts scan and test actions if uninstalled, presenting an installation prompt dialog to the user.

## 6. Optical Character Recognition Engine (`ReceiptOcrEngine`)

Powered by unbundled Google Play Services ML Kit:

- Crops bounded regions from the source bitmap according to normalized box coordinates.
- Processes cropped segments using `InputImage.fromBitmap` and ML Kit's Latin script recognizer.
- Runs `ReceiptScriptEngine.processValue` for each bounding box to apply script and regex logic before mapping.
- Fallback sanitizer for unscripted boxes:
  - Price/money fields: extracts decimal monetary amounts (e.g. `$ 45.20` -> `45.20`).
  - Date fields: extracts formatted date strings.
  - Description/text fields: joins multiline tokens into clean space-separated lines.

## 7. Background Folder Monitoring & Automation (`ReceiptWatcherService` & `ReceiptScanner`)

- **`ReceiptWatcherService`**:
  - Foreground/background service managing `ContentObserver` on target SAF tree URIs.
  - Periodic polling (every 60 seconds) ensuring image creation is caught even when DocumentProviders omit change events.
  - Starts automatically when at least one template is enabled, and tears down when all templates are disabled.
- **`ReceiptScanner`**:
  - Safely decodes images while preserving EXIF orientation (`loadOrientedBitmap`).
  - Checks OCR plug-in installation before scanning; reports plug-in requirement gracefully if uninstalled.
  - Identifies new files matching the regex pattern that have not yet been processed.
  - Runs OCR and script/regex pipelines on bounding boxes, auto-populates current date if unmapped, and appends structured rows to Exvia via `ExpenseRepository.appendRow()`.
  - Dispatches user notifications (`NotificationDispatcher`).
  - Updates Home Screen widgets (`ExpenseAppWidgetProvider.updateAllWidgets()`).
  - Records processed file names to ensure zero duplicate amends.
