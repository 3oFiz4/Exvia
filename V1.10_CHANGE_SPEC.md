# Exvia v1.10 change specification

## 1. Custom plots

Settings now contains a **Custom plot** accordion. A definition has:

- name
- x-axis source
- y-axis source
- enabled/disabled state

An enabled definition appears under **Stat → Custom plots** and produces the same three interactive plot families used by ordinary numeric keys:

1. History: cumulative box/whisker timeline
2. Accumulation: running sum
3. Normal distribution: fitted normal PDF with sample ticks

### Source syntax

Bare keys are treated as columns.

```text
price
column:price
column:date
row:index
stat:price:median
stat:price:stdv
finance:price:netCashFlow
finance:price:savingsRate
```

Supported statistical metric names include mean, median, sum, stdv, minimum, maximum, range, Q1, Q2, Q3, IQR, skew, kurtosis, variance, n, n unique, and numeric n.

Supported financial metric names include total income, total expenses, net cash flow, savings rate, expense ratio, emergency-fund months, debt-to-income, expense/income averages and medians, volatility, growth, recurring ratios, subscription burden, cash burn, reserve days, average daily balance, days until cash runs out, no-spend ratio, transaction count, and period days.

When the x source is a date column, real datetime spacing is retained and rows sharing an exact timestamp are grouped. For non-date x sources, Exvia uses sequential positions and displays the resolved x values as labels.

Statistical and financial sources are evaluated cumulatively over the visible/filtered prefix. Therefore filtering continues to affect every custom plot.

## 2. Application rename

The visible application name, launcher label, title, Settings heading, project name, GitHub-created repository description, initialization commit, and API user agent now use **Exvia**.

The Android package/application ID remains `com.example.exp_tracker` deliberately. Keeping it preserves update compatibility with already installed builds. Existing settings and the encrypted PAT are migrated/reused through legacy preference names.

## 3. Logo

The canonical editable logo is:

```text
app/src/main/assets/logo.png
```

The launcher references:

```text
app/src/main/res/drawable-nodpi/exvia_logo.png
```

A Gradle `syncExviaLogo` task copies `assets/logo.png` to the launcher resource before `preBuild`. Replace `assets/logo.png`; the next Android build synchronizes it automatically. The same asset is also shown in the Exvia title row at runtime.

## 4. Re-sync

A compact **Re-sync** action is available in the top bar. It:

- reloads the JSON file list from GitHub;
- downloads the selected file;
- replaces its local cache;
- refreshes Table, Stat, Files, filtering, finance metrics, custom metrics, and custom plots.

GitHub load failures explicitly tell the user to tap Re-sync, and the button receives an active border after an error.

## 5. Persistent GitHub file cache

Exvia stores repository metadata and raw JSON for files that have actually been opened under app-private storage.

Startup behavior:

1. Read the cached GitHub file list.
2. Reopen the last selected/default file from cache.
3. Avoid a GitHub fetch when the cached file exists.
4. Fetch only when no cache exists, an uncached file is selected, Re-sync is pressed, or Exvia successfully writes a real change.

After Amend, row update, row deletion, file creation, or file deletion, Exvia refreshes the affected cache immediately. Cache namespaces include owner, repository, branch, and folder, so changing repository settings cannot mix unrelated data.

Only app-private files are used; no storage permission is required.
